Observations from the matrix above:
  - Position 0 gives sin(0)=0 for all even dims, cos(0)=1 for all odd dims
  - Lower dimensions (left) oscillate FAST -- they encode fine-grained,
    local position differences
  - Higher dimensions (right) oscillate SLOWLY -- they encode coarse,
    long-range position information
  - Together, the full d_model-dimensional pattern is unique per position,
    like a binary counter but continuous instead of discrete

------------------------------------------------------------------------------------------
PROPERTY 1: Values are bounded in [-1, 1]
------------------------------------------------------------------------------------------

For a 512-position, 128-dim encoding:
  Minimum value: -1.000000
  Maximum value: 1.000000
  All values within [-1, 1]: True

This matters because positional encodings are ADDED to word embeddings.
If we naively used raw position integers (0, 1, 2, ... 511), position 511
would completely swamp the embedding's semantic content. Bounded sinusoids
perturb the embedding without destroying it.

------------------------------------------------------------------------------------------
PROPERTY 2: Every position gets a unique encoding
------------------------------------------------------------------------------------------

Distinct encoding vectors across 512 positions: 512 / 512
All positions uniquely encoded: True

------------------------------------------------------------------------------------------
PROPERTY 3: PE(pos + k) is a LINEAR function of PE(pos)
------------------------------------------------------------------------------------------

This is the theoretically important property. For each sin/cos frequency
pair, shifting position by a fixed offset k is exactly a 2D rotation:

    [sin(w(pos+k))]   [ cos(wk)  sin(wk)] [sin(w*pos)]
    [cos(w(pos+k))] = [-sin(wk)  cos(wk)] [cos(w*pos)]

Verifying numerically for pos=3, offset k=5, first 4 frequency bands:

    Rotation-predicted PE(8): [ 0.9894 -0.1455]
    Actual PE(8):             [ 0.9894 -0.1455]
    MATCH: True
  Frequency band 1:
    Rotation-predicted PE(8): [0.6008 0.7994]
    Actual PE(8):             [0.6008 0.7994]
    MATCH: True
  Frequency band 2:
    Rotation-predicted PE(8): [-0.2802  0.9599]
    Actual PE(8):             [-0.2802  0.9599]
    MATCH: True
  Frequency band 3:
    Rotation-predicted PE(8): [-0.8858  0.4641]
    Actual PE(8):             [-0.8858  0.4641]
    MATCH: True

  All frequency bands verified: True

WHY THIS MATTERS: because relative offsets are linear transformations,
the model can learn a single weight matrix meaning 'attend to whatever is
3 positions back' and apply it at ANY absolute position. Relative position
becomes a learnable, position-independent operation.

PROPERTY 4: Encoding similarity decays with positional distance
------------------------------------------------------------------------------------------

Dot product between PE(0) and PE(k) for increasing k:

  k = 0     dot =   64.0000   cosine similarity =  1.0000
  k = 1     dot =   62.0937   cosine similarity =  0.9702
  k = 2     dot =   57.3819   cosine similarity =  0.8966
  k = 5     dot =   47.1850   cosine similarity =  0.7373
  k = 10    dot =   42.8200   cosine similarity =  0.6691
  k = 20    dot =   38.9340   cosine similarity =  0.6083
  k = 50    dot =   34.9550   cosine similarity =  0.5462
  k = 100   dot =   30.5435   cosine similarity =  0.4772
  k = 200   dot =   19.5640   cosine similarity =  0.3057

Nearby positions have similar encodings; distant positions diverge. This
gives the model a usable, continuous notion of 'how far apart are these
two tokens' -- without ever explicitly computing a distance.

------------------------------------------------------------------------------------------
WHY THIS IS NECESSARY: attention is permutation-invariant without it
------------------------------------------------------------------------------------------

WITHOUT positional encoding:
  Attention output for original order, row for token '2':
    [ 1.5041 -0.2272  0.3093 -0.81   -2.4181  0.6611  0.8462 -0.7073]
  Attention output for shuffled order, same token now at row 0:
    [ 1.5041 -0.2272  0.3093 -0.81   -2.4181  0.6611  0.8462 -0.7073]
  IDENTICAL: True

  -> Shuffling the input just shuffles the output. The mechanism cannot
     tell the difference between 'dog bites man' and 'man bites dog'.

WITH positional encoding added:
  Original-order output for that token:  [ 2.391  -0.6983  0.5029  0.1847 -2.2854  1.6863  0.8275  0.3245]
  Shuffled-order output, same token:     [ 1.5617  0.6776  0.3249  0.2502 -2.2787  1.6513  0.8335  0.324 ]
  IDENTICAL: False

  -> Now they differ. Order information has been successfully injected,
     so the model CAN distinguish different word orders.
