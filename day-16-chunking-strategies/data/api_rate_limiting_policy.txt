ACME CORPORATION — API RATE LIMITING POLICY
Internal Engineering Reference Document
Version 1.4 — January 2026

OVERVIEW

This document describes the rate limiting behavior applied to all external API
endpoints exposed by the Acme Logistics Platform. It is intended for internal
engineering reference and for inclusion in customer-facing API documentation
where noted.

STANDARD RATE LIMITS

Free-tier API keys are limited to 60 requests per minute and 10,000 requests per
day, calculated on a rolling window basis rather than a fixed calendar window.
Professional-tier API keys are limited to 600 requests per minute and 200,000
requests per day. Enterprise-tier customers negotiate custom limits directly
with their account manager, recorded in the account configuration table rather
than enforced through the standard tier system.

RATE LIMIT HEADERS

Every API response includes three headers describing the caller's current rate
limit status: X-RateLimit-Limit (the maximum allowed requests in the current
window), X-RateLimit-Remaining (requests remaining in the current window), and
X-RateLimit-Reset (a Unix timestamp indicating when the current window resets).
Clients should treat these headers as authoritative and adjust request pacing
accordingly rather than relying on client-side request counting.

EXCEEDING RATE LIMITS

Requests exceeding the caller's rate limit receive an HTTP 429 status code with
a Retry-After header indicating the minimum number of seconds to wait before
retrying. Repeated violations (more than 10 rate-limit rejections within a
5-minute window) trigger a temporary 15-minute full suspension of the API key,
independent of the normal per-minute and per-day limits.

BURST ALLOWANCE

Professional and Enterprise tier keys receive a burst allowance equal to 20% of
their per-minute limit, permitting short traffic spikes without triggering a
429 response, provided the caller's rolling-window average remains within the
standard limit over any 60-second period.

ENDPOINT-SPECIFIC OVERRIDES

Some endpoints carry stricter limits than the account-level default due to
higher backend processing cost. The bulk shipment creation endpoint
(/v2/shipments/bulk) is limited to 10 requests per minute regardless of account
tier, since each request may create up to 500 individual shipment records. The
route optimization endpoint (/v2/routes/optimize) is limited to 30 requests per
minute per account, since each request triggers a computationally expensive
optimization run.

WEBHOOK DELIVERY RATE LIMITS

Outbound webhook deliveries from Acme's platform to a customer's registered
endpoint are not subject to the same rate limits as inbound API calls. However,
if a customer's webhook endpoint returns 5 consecutive failures (non-2xx
responses or timeouts exceeding 10 seconds), webhook delivery to that endpoint
is automatically paused for 30 minutes before automatic retry resumes.

REQUESTING A LIMIT INCREASE

Customers on the Professional tier may request a temporary or permanent rate
limit increase by submitting a request through the developer portal, which is
reviewed by the platform engineering team within 2 business days. Temporary
increases (for planned traffic events such as a product launch) are typically
approved within 24 hours given at least 5 business days' advance notice.

CHANGE HISTORY

Version 1.4 (January 2026): Added endpoint-specific override section for bulk
shipment creation and route optimization endpoints, following repeated support
tickets about unexpected 429 responses on those two endpoints specifically.

Version 1.3 (September 2025): Introduced the burst allowance for Professional
and Enterprise tiers, replacing the previous strict per-minute cap with no
burst tolerance.

Version 1.2 (April 2025): Changed rate limit windows from fixed calendar
windows to rolling windows, following customer feedback that fixed windows
created unpredictable "reset spikes" at the top of each minute.
