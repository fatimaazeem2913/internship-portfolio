Interpretation: even in this small UNTRAINED network (no learning has happened
yet -- these are random initial weights), the gradient flowing back to early
timesteps is already noticeably smaller than for recent timesteps in most runs.
This is the mathematical seed of the 'vanishing gradient' problem: at every
timestep, the gradient gets multiplied by the LSTM's weight matrices and gate
activations (values typically < 1). Multiply many such factors together across
50+ timesteps and the signal reaching early tokens shrinks multiplicatively --
in a REAL trained network over much longer sequences, this compounds severely,
meaning early tokens contribute almost nothing to the final prediction's error
signal, so the model effectively 'forgets' long-range context during training.


--- SEQUENTIAL DEPENDENCY: each timestep depends on the previous one ---

An LSTM cell's hidden state h_t and cell state c_t are computed as a FUNCTION
of h_(t-1) and c_(t-1) -- the previous timestep's output is a required INPUT
to the current timestep's computation. This is structurally different from a
Transformer, where every token's attention computation can run independently
and simultaneously.

Manually unrolling all 55 timesteps one-by-one (forced sequential loop): 28.883 ms
Each iteration of this Python loop MUST wait for the previous iteration to
finish, because h_t literally requires h_(t-1) as an argument -- there is no
way to compute timestep 30 before timestep 29 has produced its hidden state.
Contrast this with self-attention, where the representation for token 30 can
be computed in the same parallel matrix operation as token 1, since attention
only needs the FULL set of token embeddings up front -- not a running state
threaded through one timestep at a time.
