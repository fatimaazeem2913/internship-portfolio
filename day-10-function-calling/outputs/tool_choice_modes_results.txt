### 1. The Geometry of a Rainbow
Why do we see rainbows as arcs in the sky? It’s all because of the number 42. When sunlight enters a raindrop, it is refracted (bent), reflected off the back of the drop, and refracted again as it exits. While light exits at various angles, the most intense concentration of light—the angle at which the light is brightest and creates the visible rainbow—leaves the drop at **42 degrees**. 

### 2. The "33" Mystery in Mathematics
For decades, mathematicians were stumped by a problem involving "sums of three cubes." The question was: can every integer up to 100 be written as the sum of three cubed numbers (e.g., $x^3 + y^3 + z^3 = k$)? 

For a long time, the number 42 was one of the final holdouts under 100 that nobody could solve. Finally, in 2019, supercomputers using the power of the global computing grid found the solution for 42:
* $(-80538738812075974^3) + (80435758145817515^3) + (12602123297335631^3) = 42$

### 4. Biology and Origami

However, if you have a massive sheet of paper—like a mile-long roll of toilet paper—and you fold it back and forth continuously, you only need **42 folds** to reach the distance from the Earth to the Moon! ==========================================================================================
WHEN TO USE EACH MODE IN PRODUCTION
==========================================================================================

AUTO (the default): use for general-purpose assistants where you genuinely
  don't know in advance whether a given user question will need a tool --
  let the model decide per-request, exactly like function_calling_loop.py
  and multi_tool_agent.py in this project.

ANY: use when you KNOW the task always requires a tool call and want to
  eliminate the "model declines" edge case entirely -- e.g. a dedicated
  "calculate my order total" endpoint that should ALWAYS invoke your
  pricing tools, never attempt to answer from memory. Trade-off: if the
  question genuinely doesn't need a tool, ANY mode still forces one,
  potentially producing an unhelpful or irrelevant call.

NONE: use to temporarily disable tool use without removing the tool
  definitions from your code -- useful for A/B testing tool-augmented vs.
  non-tool-augmented responses, or for a "safe mode" fallback if a tool
  backend is known to be down and you'd rather get a direct (possibly
  less accurate) answer than a guaranteed failed tool call.
